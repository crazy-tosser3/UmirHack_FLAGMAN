# Аналитика — API для фронта

Базовый адрес: `/api/v1/analytics`. Все запросы идут через `api` из `src/lib/api.ts` (он сам подставляет `Authorization: Bearer <accessToken>`).

## Общее

- **Доступ:** только роли `manager` и `admin`. Остальные получают `403 FORBIDDEN`, без токена — `401 UNAUTHORIZED`.
- **Даты и время** — ISO 8601: момент времени `2026-10-11T09:30:00Z`, день `2026-10-11`.
- **Количества** — в базовой единице ингредиента (`unit`): `g` — граммы, `ml` — миллилитры, `pcs` — штуки. Дробные значения приходят числом (`240.5`).
- **Списки с пагинацией** возвращают `page`, `limit`, `total`. `page` — от 1, `limit` — 1–100 (по умолчанию 20).
- **Ошибки** — единый формат:

```json
{ "error": { "code": "VALIDATION_ERROR", "message": "...", "details": null, "requestId": "req-..." } }
```

`400 VALIDATION_ERROR` — неверный формат даты или UUID, `from` позже `to`, `limit`/`page` вне диапазона.

## Сводная таблица

| Эндпоинт | Что показывает |
|---|---|
| `GET /daily/dishes` | Сколько порций каждого блюда продано за день |
| `GET /daily/ingredients` | Сколько каждого продукта ушло за день: под заказы и в списание |
| `GET /write-offs` | Сколько продуктов списано как просроченные за период |
| `GET /deficits` | Каких продуктов чаще всего не хватало для заказов |
| `GET /stock-forecast` | Когда каждое блюдо попадёт в стоп-лист |
| `GET /supply-suggestions` | Что и сколько докупить на ближайшие дни |

## `GET /daily/dishes` — продажи блюд за день

| Параметр | По умолчанию | Описание |
|---|---|---|
| `date` | сегодня | День в формате `2026-10-11` |

**`200 OK`**

```json
{
  "date": "2026-10-11",
  "from": "2026-10-10T21:00:00Z",
  "to": "2026-10-11T21:00:00Z",
  "totalPortions": 6,
  "totalOrders": 2,
  "items": [
    { "dishId": "0190a002-...", "dishName": "Маргарита", "portions": 3, "orders": 2 },
    { "dishId": "0190a002-...", "dishName": "Сырный хлеб", "portions": 3, "orders": 1 }
  ]
}
```

| Поле | Описание |
|---|---|
| `from`, `to` | Точные границы дня в UTC (день считается по часовому поясу ресторана) |
| `totalPortions` | Всего порций за день |
| `totalOrders` | Всего заказов за день |
| `items[].portions` | Порций этого блюда |
| `items[].orders` | В скольких заказах было это блюдо |

Учитываются только оформленные заказы — отказы из-за нехватки продуктов не попадают. Сортировка — по числу порций, по убыванию. Если за день продаж не было — `items: []`.

## `GET /daily/ingredients` — расход продуктов за день

| Параметр | По умолчанию | Описание |
|---|---|---|
| `date` | сегодня | День в формате `2026-10-11` |

**`200 OK`**

```json
{
  "date": "2026-10-11",
  "from": "2026-10-10T21:00:00Z",
  "to": "2026-10-11T21:00:00Z",
  "items": [
    {
      "ingredientId": "0190a001-...",
      "ingredientName": "Моцарелла",
      "unit": "g",
      "consumedQuantity": 510,
      "writtenOffQuantity": 200,
      "totalQuantity": 710
    }
  ]
}
```

| Поле | Описание |
|---|---|
| `consumedQuantity` | Списано под заказы |
| `writtenOffQuantity` | Списано как просроченное |
| `totalQuantity` | Сумма двух полей выше |

Данные берутся из журнала движений склада — это фактическое списание по партиям. Сортировка — по общему расходу, по убыванию.

## `GET /write-offs` — списания просрочки за период

| Параметр | По умолчанию | Описание |
|---|---|---|
| `from` | `to` минус 30 дней | Начало периода, `2026-10-01T00:00:00Z` |
| `to` | сейчас | Конец периода |
| `ingredientId` | — | Только один ингредиент |
| `page`, `limit` | `1`, `20` | Пагинация |

**`200 OK`**

```json
{
  "from": "2026-09-11T09:00:00Z",
  "to": "2026-10-11T09:00:00Z",
  "items": [
    { "ingredientId": "0190a001-...", "ingredientName": "Соус", "unit": "g", "quantity": 300, "batchesCount": 1 }
  ],
  "page": 1,
  "limit": 20,
  "total": 1
}
```

| Поле | Описание |
|---|---|
| `quantity` | Сколько списано за период |
| `batchesCount` | Из скольких партий |

Сортировка — по объёму списания, по убыванию. Просрочка списывается автоматически раз в минуту.

## `GET /deficits` — нехватка продуктов

Каждый отказ в заказе из-за нехватки продукта записывается. Эндпоинт показывает, каких продуктов не хватало чаще всего.

| Параметр | По умолчанию | Описание |
|---|---|---|
| `from` | `to` минус 30 дней | Начало периода |
| `to` | сейчас | Конец периода |
| `ingredientId` | — | Только один ингредиент |
| `page`, `limit` | `1`, `20` | Пагинация |

**`200 OK`**

```json
{
  "from": "2026-09-11T09:00:00Z",
  "to": "2026-10-11T09:00:00Z",
  "items": [
    {
      "ingredientId": "0190a001-...",
      "ingredientName": "Моцарелла",
      "unit": "g",
      "deficitCount": 2,
      "missingQuantity": 280,
      "lastDeficitAt": "2026-10-11T08:07:02Z"
    }
  ],
  "page": 1,
  "limit": 20,
  "total": 1
}
```

| Поле | Описание |
|---|---|
| `deficitCount` | Сколько раз из-за этого продукта отказали в заказе |
| `missingQuantity` | Сколько суммарно не хватило |
| `lastDeficitAt` | Когда это случилось последний раз |

Сортировка — по `deficitCount`, по убыванию.

## `GET /stock-forecast` — прогноз стоп-листа

Для каждого активного блюда показывает, когда оно попадёт в стоп-лист, если не будет новых поставок.

| Параметр | По умолчанию | Описание |
|---|---|---|
| `ingredientId` | — | Только блюда с этим ингредиентом |
| `page`, `limit` | `1`, `20` | Пагинация |

**`200 OK`**

```json
{
  "generatedAt": "2026-10-11T09:00:00Z",
  "horizonDays": 30,
  "consumptionWindowDays": 7,
  "items": [
    {
      "dishId": "0190a002-...",
      "dishName": "Пицца Маргарита",
      "availablePortions": 12,
      "stopAt": "2026-10-13T18:07:29Z",
      "cause": "consumption",
      "limitingIngredient": {
        "ingredientId": "0190a001-...",
        "ingredientName": "Томатный соус",
        "unit": "g",
        "availableQuantity": 1020,
        "requiredPerPortion": 80,
        "dailyConsumption": 240
      }
    }
  ],
  "page": 1,
  "limit": 20,
  "total": 1
}
```

| Поле | Описание |
|---|---|
| `availablePortions` | Сколько порций можно приготовить прямо сейчас |
| `stopAt` | Когда блюдо уйдёт в стоп. `null` — не в ближайшие 30 дней (`horizonDays`) |
| `cause` | Причина: `consumption` — закончится по расходу, `expiry` — продукт испортится, `already_stopped` — уже в стопе |
| `limitingIngredient` | Продукт, который закончится первым |
| `dailyConsumption` | Средний расход этого продукта в день |

Как считается: средний расход берётся за последние 7 дней (`consumptionWindowDays`). Дальше моделируется остаток: продукт тратится сначала из партий с ближайшим сроком, а остаток партии при истечении срока пропадает. Сортировка — по `stopAt`, ближайшие первыми, `null` в конце.

Пока заказов мало (первые часы работы), расход и прогноз могут быть завышены.

## `GET /supply-suggestions` — что докупить

Показывает продукты, которых не хватит на ближайшие `coverDays` дней, и сколько их докупить.

| Параметр | По умолчанию | Описание |
|---|---|---|
| `coverDays` | `3` | На сколько дней вперёд считать, 1–30 |

**`200 OK`**

```json
{
  "generatedAt": "2026-10-11T09:00:00Z",
  "coverDays": 3,
  "items": [
    {
      "ingredientId": "0190a001-...",
      "ingredientName": "Бекон",
      "unit": "g",
      "availableQuantity": 0,
      "dailyConsumption": 360,
      "depletionAt": "2026-10-11T09:00:00Z",
      "suggestedQuantity": 1140
    }
  ]
}
```

| Поле | Описание |
|---|---|
| `availableQuantity` | Сколько сейчас пригодного остатка |
| `dailyConsumption` | Средний расход в день |
| `depletionAt` | Когда остатка не хватит даже на одну порцию. `null` — не в ближайшие 30 дней |
| `suggestedQuantity` | Сколько докупить, в единицах `unit`, округлено вверх |

Учитывается, что часть текущих партий испортится раньше, чем будет израсходована. В список попадают только продукты, которых не хватит. Сортировка — по `depletionAt`, срочные первыми. Пагинации нет.

Ошибка: `400 VALIDATION_ERROR` — `coverDays` вне 1–30.

---

## Часовой пояс

Границы дня в `/daily/*` считаются по часовому поясу ресторана. Иначе заказ в 01:00 по Москве попал бы во «вчера». Пояс задаётся на бэкенде:

```properties
app.analytics.zone=${APP_TIMEZONE:Europe/Moscow}
```

Остальные эндпоинты принимают и возвращают время в UTC.

## Пример запроса

```ts
import api from '@lib/api';

const { data } = await api.get('/analytics/daily/dishes', { params: { date: '2026-10-11' } });
const forecast = await api.get('/analytics/stock-forecast', { params: { page: 1, limit: 20 } });
```
